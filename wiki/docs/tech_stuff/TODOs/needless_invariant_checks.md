# Лишние проверки: тип не говорит, чему верить

После чистки страховок в rmmr/Eltanin видно не баг копипасты, а дыру в семантике.

Writing/Reading уже смотрят на нормализованный мир: системные аспекты (Core, Manager, `Unit_group`, Clock, Assets на Core) уже рождены и уже истинны. Не доказывать их в каждом `Actions`. Недоверие, починка, «а вдруг забыли группу» — это `Reacting` / нормализация патча.

Сейчас это **не читается с типа**. `optional<Id>`, `singleton() → optional`, `exists` на группе — всё выглядит как «надо проверить». Разработчик честно пишет `if (not …) refuse` / `if (not exists) extend`. Логика «кто хозяин инварианта» размазывается по всем caller’ам. Позвоночник мира чинят в десяти местах вместо точки рождения (`Interface::create`, `createScene`, `Runtimes::install`).

Нужно, чтобы было видно без саги: *этот* id/группа/синглтон в этом контексте уже факт; *этот* — вход операции (файл, имя материала, опциональный Flat2d). Пока тип врёт одинаково про оба — проверки будут плодиться снова.

## Довесок: singleton как `optional`

`Core::Global::singleton` (и Clock так же) семантически не optional. После рождения синглтон *есть*: Reading/Writing читают уже заполненное поле. Уместен просто `Id`.

Технически поле живёт на Global аспекта, а Global есть и до `Interface::create`. `Id` пустым быть не умеет; `optional` — единственный понятный сейчас стенд-ин «ещё не родили». Как сказать «в живой сессии это `Id`, а до рождения поля нет» — неясно: отдельный тип контекста, phantom, required-after-first-commit у fQSM — всё ещё не дизайн, а вопрос.

Пока `optional` остаётся в типе, каждый caller снова получает сигнал «проверь». Даже если договор мира уже другой.
